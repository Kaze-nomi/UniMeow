# Список пользовательских сценариев UniMeow

## 🔐 Сценарии аутентификации

### Регистрация через Google OAuth
**Предусловия**: Пользователь не зарегистрирован в системе

**Шаги:**
1. Пользователь нажимает кнопку "Sign up with Google" на странице регистрации
2. Frontend отправляет запрос к API Gateway
3. API Gateway перенаправляет запрос в User Service
4. User Service инициирует процесс OAuth с Google
5. Пользователь выбирает аккаунт Google для регистрации
6. Google возвращает данные пользователя (email, имя)
7. User Service создает нового пользователя с привязкой к Google аккаунту
8. Генерируется JWT токен
9. Пользователь автоматически входит в систему
10. Пользователь заполняет данные своего аккаунта

**Результат**: Новый пользователь зарегистрирован и аутентифицирован

### Вход через Google OAuth
**Предусловия**: Пользователь уже зарегистрирован через Google OAuth

**Шаги:**
1. Пользователь нажимает "Login with Google" на странице входа
2. Frontend → API Gateway → User Service → Google OAuth
3. User Service находит существующего пользователя по email из Google
4. Генерируется новый JWT токен
5. Пользователь успешно входит в систему

**Результат**: Пользователь аутентифицирован в системе

### Верификация студенческого/сотруднического email
**Предусловия**: Пользователь аутентифицирован в системе

**Шаги:**
1. Пользователь в личном кабинете вводит email университета (university@edu.ru)
2. Frontend отправляет запрос через API Gateway в User Service
3. User Service проверяет email среди списка заранее определённых почт университетов студентов/сотрудников
4. Если код совпадение есть, то User Service генерирует 6-значный проверочный код, иначе возвращает ошибку
5. User Service публикует событие USER_VERIFICATION_REQUESTED в Kafka
6. Notification Service получает событие и отправляет email через SMTP
7. Пользователь получает email и вводит код в приложении
8. User Service проверяет код и устанавливает флаг is_student_verified/is_employee_verified = true
9. User Service возвращает сообщение об успешной верификации

**Результат**: Статус пользователя подтвержден

## 📝 Сценарии работы с контентом

### Создание поста
**Предусловия**: Пользователь аутентифицирован

**Шаги:**
1. Пользователь пишет текст "Привет всем!" и нажимает "Опубликовать"
2. Frontend отправляет запрос через API Gateway (с JWT токеном) в Post Service
3. Post Service сохраняет пост в базу данных
4. Post Service публикует событие POST_CREATED в Kafka
5. Post Service возвращает сообщение об успехе
6. Feed Service получает событие POST_CREATED:
   - С помощью некоторого алгоритма кэширует пост в Redis

**Результат**: Пост создан и добавлен в Feed Service

### Загрузка медиафайлов при создании поста
**Предусловия**: Пользователь аутентифицирован

**Шаги:**
1. Пользователь выбирает файлы для загрузки при создании поста
2. Frontend отправляет каждый файл в Media Service: uploadFile()
3. Media Service возвращает для каждого файла: {fileId, url}
4. Frontend отправляет запрос в Post Service: createPost с массивом fileId
5. Post Service сохраняет пост с прикрепленными медиафайлами: post.media_files = ["fileId1", "fileId2"]

**Результат**: Создан пост с прикрепленными медиафайлами

### Просмотр ленты новостей

**Шаги:**
1. Пользователь открывает главную страницу (/feed)
2. Frontend отправляет запрос через API Gateway (с JWT или без в зависимости от того аунтефицирован ли пользователь) в Feed Service
3. Feed Service извлекает userId из JWT токена (если он есть)
4. Feed Service получает из Redis список ID постов (для аутентифицированного пользователя по userId, для незарегистрированного пользователя все *популярные* посты)
5. Feed Service достаёт полные данные постов и юзеров по их ID из Redis
6. Post Service возвращает полные данные постов

**Результат**: Пользователь видит свою ленту новостей

### Просмотр постов конкретного пользователя

**Шаги:**
1. Пользователь переходит на страницу /{username}
2. Frontend отправляет запрос через API Gateway в User Service: GetUserData(username)
3. User Service возвращает userId или ошибку о несуществующем пользователе
4. API Gateway отправляет запрос в Feed Service: GetUserPosts(id={userId})
5. Feed Service возвращает все посты пользователя {username}

**Результат**: Пользователь видит все посты указанного пользователя

### Удаление поста
**Предусловия**: Пользователь аутентифицирован и является автором поста

**Шаги:**
1. Пользователь нажимает "Удалить" у своего поста
2. Frontend → API Gateway → Post Service: DeletePost(userId, postId)
3. Post Service проверяет что пользователь - автор поста
4. Post Service удаляет пост из БД
5. Post Service публикует событие POST_DELETED в Kafka
6. Feed Service получает POST_DELETED → удаляет postId из всех лент
7. Interaction Service получает POST_DELETED → удаляет все лайки/комментарии поста

**Результат**: Пост полностью удален из системы

## 👥 Сценарии социального взаимодействия

### Подписка на пользователя
**Предусловия**: Пользователь аутентифицирован

**Шаги:**
1. Пользователь нажимает "Подписаться" на странице пользователя 456
2. Frontend → API Gateway → Interaction Service: FollowUser(sourceUserId=123, targetUserId=456)
3. Interaction Service сохраняет подписку в БД
4. Interaction Service публикует событие USER_FOLLOWED в Kafka
5. Feed Service получает USER_FOLLOWED:
   - Добавляет посты targetUserId в ленту sourceUserId
6. Notification Service получает USER_FOLLOWED → отправляет уведомление targetUserId

**Результат**: Пользователь подписан на другого пользователя

### Лайк поста
**Предусловия**: Пользователь аутентифицирован, пост существует

**Шаги:**
1. Пользователь нажимает "лайк" под постом 789
2. Frontend → API Gateway → Interaction Service: LikePost(postId=789)
3. Interaction Service сохраняет лайк в БД
4. Interaction Service публикует событие POST_LIKED в Kafka
5. Notification Service получает POST_LIKED → отправляет уведомление автору поста

**Результат**: Пост отмечен как понравившийся

### Добавление комментария
**Предусловия**: Пользователь аутентифицирован, пост существует

**Шаги:**
1. Пользователь пишет комментарий "Отличный пост!" под постом 789
2. Frontend → API Gateway → Interaction Service: AddComment(postId=789, content)
3. Interaction Service сохраняет комментарий в БД
4. Interaction Service публикует событие COMMENT_ADDED в Kafka
5. Notification Service получает COMMENT_ADDED → отправляет уведомление автору поста

**Результат**: Комментарий добавлен к посту

## 🛠️ Сценарии управления аккаунтом

### Редактирование профиля
**Предусловия**: Пользователь аутентифицирован

**Шаги:**
1. Пользователь в настройках меняет имя на "Иван", фамилию на "Иванов", username на "ivanBoss2007"
2. Frontend → API Gateway → User Service: UpdateProfile({name: "Иван", surname: "Иванов", username: "ivanBoss2007"})
3. User Service обновляет данные пользователя в БД

**Результат**: Профиль пользователя обновлен

### Выход из системы
**Предусловия**: Пользователь аутентифицирован

**Шаги:**
1. Пользователь нажимает "Выйти"
2. Frontend удаляет JWT токен из localStorage
3. Все последующие запросы без токена отклоняются

**Результат**: Пользователь вышел из системы
